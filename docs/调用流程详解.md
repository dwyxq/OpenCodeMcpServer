## 二、启动流程

### 2.1 OpenCode 读取配置

OpenCode 启动时读取 `~/.config/opencode/opencode.json`：

```json
{
  "provider": {
    "SuperModel": {
      "npm": "@ai-sdk/openai-compatible",
      "options": {
        "baseURL": "http://127.0.0.1:5679/v1",
        "apiKey": ""
      },
      "models": {
        "SuperModel": { "name": "SuperModel", "limit": { "context": 131072, "output": 8192 } }
      }
    }
  },
  "mcp": {
    "OpenCodeMcpServer": {
      "type": "local",
      "command": ["D:\\LiHWork\\OpenCodeMcpServer\\bin\\Debug\\net10.0\\win-x64\\OpenCodeMcpServer.exe"],
      "environment": {
        "MODELSCOPE_API_KEY": "ms-xxxx",
        "OPENROUTER_API_KEY": "sk-or-xxxx",
        "NVIDIA_NIM_API_KEY": "nvapi-xxxx",
        ...
      },
      "enabled": true
    }
  }
}
```

### 2.2 MCP 进程启动

1. OpenCode 根据 `mcp.OpenCodeMcpServer.command` 启动 `OpenCodeMcpServer.exe`
2. OpenCode 将 `environment` 块中的变量注入为进程环境变量
3. OpenCode 通过 stdin 与服务器建立 JSON-RPC 2.0 连接

### 2.3 服务器内部初始化

`Program.cs` 执行：

```
1. 加载 appsettings.json 配置
2. 注册 DI 服务：
   - IProviderHealthService (ProviderHealthService)
   - IChatCompletionProxyService (ChatCompletionProxyService)
   - IModelDiscoveryService (ModelDiscoveryService)
   - IModelCacheRefreshService (ModelCacheRefreshService)
   - IPromptManagementService (PromptManagementService)
   - ISkillManagementService (SkillManagementService)
3. 注册 IHostedService：
   - ModelCacheRefreshService（定时刷新模型缓存 + 健康探测）
   - OpenAiCompatibleHttpServer（Kestrel HTTP 网关）
4. 注册 MCP 服务器：
   - AddMcpServer().WithStdioServerTransport().WithToolsFromAssembly()
5. app.RunAsync() 启动主循环
```

### 2.4 HTTP 网关启动

`OpenAiCompatibleHttpServer.StartAsync()`：

```
1. 读取 HttpServer 配置（Enabled/Url/ApiKey/IncludeRealModels）
2. 创建 Kestrel WebApplication
3. 鉴权中间件：
   - ApiKey 非空 → 要求 Authorization: Bearer <ApiKey>
   - ApiKey 为空 → 允许所有请求（_ => true）
4. 注册路由：
   - GET  /v1/models → 返回固定别名 SuperModel
   - GET  /models → 同上（兼容省略 /v1 前缀）
   - POST /v1/chat/completions → 代理转发
5. builder.WebHost.UseUrls(cfg.Url) → 监听 http://127.0.0.1:5679
6. app.StartAsync() 启动监听
```

## 三、两种调用路径

### 路径 A：MCP stdio 工具调用

OpenCode 通过 stdin 发送 JSON-RPC 2.0 消息调用 MCP 工具：

```
OpenCode → stdin → MCP Server → ProviderProxyTools.ChatCompletion() → ChatAsync()
```

**MCP 工具列表（26个）：**

| 工具名 | 功能 |
|---|---|
| `chat_completion` | 代理转发 chat/completions 请求 |
| `provider_models` | 列出提供商及模型目录 |
| `provider_status` | 提供商健康排序报告 |
| `check_provider_health` | 触发主动健康探测 |
| `list_prompts` / `get_prompt` | 提示词管理 |
| `list_skills` / `get_skill` | 技能管理 |
| ... | 其他工具 |

**调用示例：**

```json
{
  "jsonrpc": "2.0",
  "method": "tools/call",
  "params": {
    "name": "chat_completion",
    "arguments": {
      "model": "SuperModel",
      "messagesJson": "[{\"role\":\"user\",\"content\":\"hello\"}]"
    }
  },
  "id": 1
}
```

### 路径 B：HTTP 网关调用

OpenCode 选择 SuperModel provider 后，通过 HTTP 直接调用：

```
OpenCode → HTTP POST → http://127.0.0.1:5679/v1/chat/completions → ChatAsync()
```

**请求流程：**

```
1. OpenCode 发送 POST /v1/chat/completions
   - Headers: Authorization: Bearer <apiKey>（apiKey 为空则不发送）
   - Body: {"model":"SuperModel","messages":[...],"stream":true/false}

2. Kestrel 鉴权中间件检查 Bearer token
   - ApiKey 为空 → 允许所有请求
   - ApiKey 非空 → 要求 Bearer 匹配

3. OpenAiCompatibleHttpServer 路由处理：
   - 解析 model（缺省用别名 SuperModel）
   - ReadMessages() 解析消息列表（含 tool_call_id + tool_calls）
   - 解析 provider_id / strategy / session_id / capabilities
   - 构造 ChatProxyRequest

4. stream=true → 调用 ChatStreamAsync()（SSE 流式）
   stream=false → 调用 ChatAsync()（非流式）

5. 返回 OpenAI 兼容 JSON 或 SSE 流
```

## 四、聊天代理核心流程

### 4.1 候选提供商解析（ResolveCandidates）

```
1. GetConfiguredProviders() → 获取所有已配置提供商
2. 过滤：Enabled && !IsUnavailableForRouting（排除禁用 + 冷却中）
3. 分两种模式：
   - 别名模式（model=SuperModel）：所有有可用模型的提供商
   - 普通模式（model=具体模型名）：按模型归属 + 能力过滤
4. 按健康评分排序
5. 应用策略：auto（健康择优）/ sticky（会话粘滞）/ balanced（轮询均衡）
```

### 4.2 API Key 解析（ResolveApiKey）

三级优先级：

```
1. ApiKeys:CustomProviders[providerId]   ← appsettings.json 配置
2. endpoint.ApiKey                         ← 提供商配置中的 ApiKey
3. endpoint.ApiKeyEnvVar → 环境变量       ← opencode.json environment 注入
```

示例：
- appsettings.json: `"ApiKeyEnvVar": "MODELSCOPE_API_KEY"`
- opencode.json: `"MODELSCOPE_API_KEY": "ms-xxxx"`
- 运行时：`Environment.GetEnvironmentVariable("MODELSCOPE_API_KEY")` → `"ms-xxxx"`

### 4.3 请求构建与发送（BuildHttpRequest + SendOnceAsync）

```
BuildHttpRequest():
  payload = {
    "model": actualModel,          ← 提供商实际模型名
    "messages": [
      {
        "role": "user",
        "content": "...",
        "tool_call_id": "call_xxx",  ← 透传（tool 角色必填）
        "tool_calls": [...]          ← 透传（assistant 角色）
      }
    ],
    "stream": false/true
  }

SendOnceAsync():
  1. BuildHttpRequest() → HttpRequestMessage
  2. ApplyAuthHeaders() → 添加 Authorization: Bearer <key>
  3. client.SendAsync() → 发送到上游
  4. 非 2xx → throw ProxyUpstreamException
     - 429 → ReportRateLimited（限流避让）
     - 其他 → ReportFailure（异步降级）
  5. 2xx → 返回响应 body
```

### 4.4 故障转移

```
ChatAsync() 循环：

foreach (endpoint in candidates.Take(maxAttempts)) {
    try {
        json = await SendOnceAsync(endpoint, ...)
        → 成功：ReportSuccess，返回 ChatProxyResult(success=true)
    } catch (ProxyUpstreamException) {
        → 失败：ExtractShortReason + MaskKey → 记录原因
        → 异步 Task.Run(ReportFailure) → 不阻塞下一轮
        → continue 尝试下一个提供商
    }
}

全部失败 → Failure(FormatTried(tried), lastError)
```

**错误信息格式：**

```
agnes-ai-cn(余额不足："AGNES_CN_API_KEY" "sk-8****dYhS") ->
openrouter(限流："OPENROUTER_API_KEY" "sk-o****937c") ->
nvidia-nim(服务异常："NVIDIA_NIM_API_KEY" "nvap****3b6-")
```

### 4.5 健康评分机制

```
ProviderHealthService：

- 成功：Score += 正向权重，清零失败计数
- 失败：Score -= 负向权重，失败计数 +1
- 连续失败 ≥3 次 → CooldownUntil = now + 15分钟
- 429 限流 → RetryAfterAt = now + retryAfterMs

IsUnavailableForRouting(providerId)：
  return IsRateLimited(providerId) || IsInCooldown(providerId)

GetRankedProviders()：
  按 Score 降序排列
```

## 五、SSE 流式转发

```
ChatStreamAsync():

1. force stream=false 发上游（避免上游不支持 stream）
2. foreach (endpoint in candidates) {
       SendOnceStreamAsync(endpoint, stream=true)
       → 成功：逐行读取上游 SSE → yield return "data: {...}\n\n"
       → 失败：记录原因，continue 下一家
   }
3. 全部失败 → SerializeSseError(lastError)
```

## 七、完整调用时序

```
用户在 OpenCode 中选择 SuperModel 发送消息
        │
        ▼
OpenCode 构造 HTTP 请求
POST http://127.0.0.1:5679/v1/chat/completions
{"model":"SuperModel","messages":[{"role":"user","content":"hello"}],"stream":true}
        │
        ▼
Kestrel 接收请求
        │
        ├─ 鉴权中间件检查 Bearer token
        │
        ▼
OpenAiCompatibleHttpServer.MapPost("/v1/chat/completions")
        │
        ├─ ReadMessages() → ChatMessage[] (含 tool_call_id/tool_calls)
        ├─ 构造 ChatProxyRequest
        │
        ▼
ChatCompletionProxyService.ChatStreamAsync(request)
        │
        ├─ IsModelAlias("SuperModel") → true
        ├─ ResolveCandidates(request, alias=true)
        │   ├─ GetConfiguredProviders() → 过滤 Enabled && !IsUnavailableForRouting
        │   ├─ 按健康评分排序
        │   └─ 返回 List<ProviderEndpointConfig>
        │
        ▼
foreach (endpoint in candidates)
        │
        ├─ ResolveApiKey(endpoint)
        │   ├─ ApiKeys:CustomProviders[id] → 空
        │   ├─ endpoint.ApiKey → null
        │   └─ Environment.GetEnvironmentVariable(endpoint.ApiKeyEnvVar) → "ms-xxxx"
        │
        ├─ BuildHttpRequest(endpoint, request, actualModel, stream=true)
        │   ├─ payload = {"model":"...", "messages":[...], "stream":true}
        │   ├─ 透传 tool_call_id + tool_calls
        │   └─ ApplyAuthHeaders → Authorization: Bearer ms-xxxx
        │
        ├─ client.SendAsync(httpRequest, ResponseHeadersRead)
        │
        ├─ 成功 (2xx):
        │   ├─ ReportSuccess(providerId, latency)
        │   ├─ 逐行读取 SSE 流 → yield return "data: {...}\n\n"
        │   └─ 完成
        │
        └─ 失败 (非 2xx):
            ├─ 429 → ReportRateLimited → 进入限流避让
            ├─ 其他 → ExtractShortReason + MaskKey
            ├─ Task.Run(ReportFailure) → 异步降级
            └─ continue → 尝试下一个提供商
```

## 八、关键设计决策

1. **HTTP 网关 + MCP stdio 并行**：一个进程同时服务 HTTP 请求和 MCP 工具调用
2. **环境变量注入**：API Key 不写入 appsettings.json，通过 opencode.json environment 注入
3. **异步健康降级**：ReportFailure 用 Task.Run 不阻塞故障转移循环
4. **统一 BuildHttpRequest**：非流式和流式路径共享 payload 构建，确保 tool_call_id 透传
5. **Key 脱敏显示**：错误信息中 Key 显示为 `xxxx****xxxx` 格式，不泄露完整值
6. **别名路由**：model=SuperModel 时自动选择健康评分最高的提供商及其默认模型
